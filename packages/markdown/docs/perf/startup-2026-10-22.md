# Startup / first-open (2026-10-22)

Aggressive cold-path reductions for opening a `.md` in Lumière Live Preview.
Measured on this worktree vs `origin/main` at `c9f809d6` (production build).

## Bundle (production)

| Asset | Before | After | Delta |
| --- | ---: | ---: | ---: |
| Webview `editor.js` entry | 2,135,061 B (~2.13 MB) | 112,130 B (~0.11 MB) | **−95%** |
| Webview static import graph from `editor.js` | ≈ entry (features inlined) | 842,942 B (~0.82 MB) | **−~1.29 MB initial fetch** |
| Host `extension.js` | 1,058,649 B (~1.03 MB) | 893,573 B (~0.87 MB) | **−165 KB (−16%)** |

What left the cold path:

- **Webview features** (tables, math, diagrams, onlineVideos, vim, …) load via
  dynamic `import()` when enabled; Vim’s `@replit/codemirror-vim` (~123 KB)
  is no longer pulled in by tables when Vim is off.
- **Host dialect** no longer ships CodeMirror `LanguageSupport` /
  `@codemirror/view` (~150 KB) or the HTML `createRenderer` into the extension
  host; vault indexing keeps the Lezer parser + metadata only.
- **Panel HTML** is set before panel host plugins configure, so `editor.js`
  download overlaps host work. `ready` still awaits `settled()` + settings
  `prepare`.

## Harness note

`scripts/profile-open.ts` still uses the monolithic `fake-host.js` browser
harness (all features eagerly present), so it does **not** reflect webview
chunk laziness. On this box: 24 blocks ≈ 386 ms, 16,000 blocks ≈ 1,285 ms
open. Prefer native `test/vscode/perf.spec.ts` (`mw:*` marks) for end-to-end
first paint once a VS Code run is available.

## Residual opportunities

- Split `markdown/html/helpers` + heading-extract off markdown-it on the host
  (~52 KB still in `extension.js`).
- Defer workbench window plugins (graph, marp, …) until after first editor ready.
- Parallelize independent `PluginSwitch` starts (still sequential per name).
- Lazy YAML when a note has no frontmatter (properties path).
